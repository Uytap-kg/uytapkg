# Интеграция SMS-сервиса Nikita OTP (smspro.nikita.kg)

Документация по отправке и проверке одноразовых SMS-кодов подтверждения (OTP) через API шлюза **Nikita** в платформе UyTap.

---

## 1. Переменные окружения (.env)

Для работы SMS-сервиса необходимо задать следующие параметры в `back-end/.env`:

```env
# ==============================================================================
# SMS-сервис Nikita OTP (smspro.nikita.kg)
# ==============================================================================

# Обязательный API-ключ из личного кабинета (вкладка «СЕРВИС OTP»)
NIKITA_API_KEY=your-nikita-api-key

# Базовый URL API (по умолчанию https://smspro.nikita.kg)
NIKITA_BASE_URL=https://smspro.nikita.kg

# Таймаут запроса в миллисекундах (по умолчанию 10000)
NIKITA_TIMEOUT_MS=10000

# Кулдаун повторной отправки на один номер в секундах (по умолчанию 60)
NIKITA_RESEND_COOLDOWN_SEC=60

# Лимит отправок на один номер в час (по умолчанию 5)
NIKITA_HOURLY_LIMIT_PHONE=5

# Лимит отправок с одного IP в час (по умолчанию 20)
NIKITA_HOURLY_LIMIT_IP=20
```

> [!IMPORTANT]
> Если `NIKITA_API_KEY` не задан, при вызове отправки или проверки SMS бэкенд выбросит понятную ошибку `assertNikitaConfigured` с указанием шагов настройки.

---

## 2. Что нужно настроить в личном кабинете Nikita

Перейдите в личный кабинет [smspro.nikita.kg](https://smspro.nikita.kg) на вкладку **«СЕРВИС OTP»**:

1. **API-ключ (X-API-KEY):**
   - Сгенерируйте API-ключ в кабинете и скопируйте его в переменную `NIKITA_API_KEY` на сервере.
2. **Имя отправителя (Sender ID):**
   - Зарегистрируйте буквенное имя отправителя (например, `UyTap`). Имя должно пройти модерацию у операторов связи Кыргызстана.
3. **Шаблон текста SMS-сообщения:**
   - Настройте текст сообщения с обязательными шаблонами `%code%` и `%time%`.
   - Пример: `Ваш код подтверждения UyTap: %code%. Действителен %time% мин.`
4. **Параметры кода:**
   - Длина кода: 4 или 6 цифр (рекомендуется 6 цифр).
   - Сложность кода: только цифры (`0-9`).
   - Время жизни кода (`%time%`): например, 5 или 10 минут.
5. **IP Whitelist (Белый список IP-адресов):**
   - Если в кабинете включена фильтрация по IP, добавьте внешний статический IP-адрес вашего сервера (VPS). При несовпадении IP сервис возвращает ошибку `status: 3 (Bad IP-address)`.
6. **Баланс счёта:**
   - Убедитесь, что на лицевом счёте достаточно средств для тарификации SMS. При нулевом балансе шлюз возвращает `status: 4 (Not Enough Money)`.

> [!NOTE]
> Сервис Nikita сам генерирует и отправляет код, а также проверяет его валидность и срок жизни. Сервер UyTap не генерирует и не хранит открытый SMS-код, обеспечивая максимальную безопасность.

## 3. Архитектура и безопасность

- **Нормализация номера телефона:**
  - Номера приводятся к международному формату без `+`: `996XXXXXXXXX` (12 цифр).
  - Форматы `0770123456`, `+996 770 12-34-56`, `770123456` автоматически приводятся к `996770123456`.
- **Уникальный `transaction_id`:**
  - Генерируется на каждую отправку как 32-значный hex-хеш (UUID v4 без дефисов).
- **Сетевые сбои и безопасный повтор:**
  - При ошибке соединения до получения ответа шлюза выполняется ровно 1 повторный запрос с **НОВЫМ** `transaction_id`, исключая блокировку `status: 10 (Invalid Transaction ID)` и двойное списание.
- **Ограничение подбора (Brute-force protection):**
  - Максимум 5 попыток ввода кода на один `token`. После 5 неверных попыток сессия токена немедленно аннулируется.
- **Одноразовость токена:**
  - После успешного подтверждения токен сразу удаляется из памяти сервера.
- **Маскирование в логах:**
  - Номера телефонов логируются строго в виде `99677****56`. OTP-коды и секретные ключи **никогда** не попадают в логи.

## 4. Ручная проверка через curl

### Шаг 1. Отправка SMS с кодом

```bash
curl -X POST http://localhost:5000/api/auth/send-otp \
  -H "Content-Type: application/json" \
  -d '{
    "phone": "+996 (770) 12-34-56"
  }'
```

**Ожидаемый ответ при успехе (HTTP 200):**
```json
{
  "success": true,
  "message": "Код подтверждения отправлен по SMS",
  "token": "a1b2c3d4e5f6..."
}
```

---

### Шаг 2. Проверка полученного кода

Можно передать номер телефона и код:

```bash
curl -X POST http://localhost:5000/api/auth/verify-otp \
  -H "Content-Type: application/json" \
  -d '{
    "phone": "996770123456",
    "code": "123456"
  }'
```

Либо передать `token` (полученный из шага 1) и код:

```bash
curl -X POST http://localhost:5000/api/auth/verify-otp \
  -H "Content-Type: application/json" \
  -d '{
    "token": "a1b2c3d4e5f6...",
    "code": "123456"
  }'
```

**Ожидаемый ответ при успехе (HTTP 200):**
```json
{
  "success": true,
  "message": "Номер телефона успешно подтвержден"
}
```

**Примеры ответов при ошибках (HTTP 400):**
- Неверный код:
  ```json
  {
    "success": false,
    "message": "Неверный код",
    "attemptsLeft": 4
  }
  ```
- Истёк срок жизни кода:
  ```json
  {
    "success": false,
    "message": "Срок действия кода истёк, запросите новый"
  }
  ```
- Превышен лимит попыток:
  ```json
  {
    "success": false,
    "message": "Превышено максимальное число попыток ввода кода (5). Запросите новый код"
  }
  ```
- Превышение кулдауна отправки (HTTP 429):
  ```json
  {
    "success": false,
    "message": "Повторная отправка возможна через 45 секунд",
    "retryAfter": 45
  }
  ```
