# Нагрузочные и конкурентные тесты UyTap (`back-end/load-tests/`)

Набор воспроизводимых тестов для проверки устойчивости бэкенда UyTap под нагрузкой, при гонках платежей и при запуске в многопроцессном режиме (PM2 cluster / несколько контейнеров).

> **Безопасность:** Скрипты поднимают изолированный тестовый HTTP-сервер на `127.0.0.1:0` и автоматически мокают внешние платные API (Nikita SMS, Resend, Claude/Gemini, O!Dengi) и таблицы БД. Продакшн-база и платные квоты **никогда** не затрагиваются.

## Как запустить

Из папки `back-end/`:

```bash
# Полный прогон всех 5 сценариев (чтение каталога, флуд OTP/auth, семафор AI, шторм вебхуков оплаты, 2 процесса)
node load-tests/run-all.mjs

# Отдельная проверка синхронизации состояния между 2 процессами (OTP, лимиты, cron lease)
node load-tests/multi-process-check.mjs
```

## Сценарии и критерии прохождения

| № | Сценарий | Что проверяет | Критерий прохождения |
|---|---|---|---|
| **1** | Чтение каталога, фильтров, карты, карточки и профиля (`200` запросов, `20` параллельно) | Пагинация, экранирование `%`/`_`, `publicCache`, пакетный буфер просмотров (`counterBatcher`) | `0%` ошибок 5xx, `200/200` ответов `200 OK`, `p95 < 50 мс`, запись просмотров в БД сведена к 1 батчу |
| **2** | Флуд на `POST /api/auth/forgot-password` / `send-otp` с 1 IP и ротацией `email` (`25` запросов) | Двойной барьер P2-01 (`sendOtpIpLimiter` max=5/15мин с IP + лимит на цель) и защита от перебора аккаунтов | Первые 5 запросов с IP получают одинаковый `200 OK`, остальные `20` запросов блокируются `429 Too Many Requests` |
| **3** | Всплеск `40` одновременных запросов к AI-поиску | Семафор `aiSearchSemaphore` (`maxConcurrent=5`, `maxQueue=15`) | Одновременно выполняется `<= 5` запросов, `20` запросов обрабатываются (`200 OK`), `20` сверх очереди мгновенно получают `503` без падения процесса |
| **4** | Шторм `30` одновременных вебхуков `POST /api/payments/webhook` для одного `order_id` | In-process mutex `withOrderFulfillmentLock` + атомарный `tryClaimPaymentFulfillment` в БД + RPC `activate_subscription_atomic` | `0%` ошибок 5xx, подписка активируется строго **1 раз** (`webhookSubscriptionActivations === 1`), `fulfilled_at` заполнен |
| **5** | Работа в 2 процессах (`multi-process-check.mjs`) | Общие таблицы `phone_otp_sessions`, `rate_limit_counters`, `cron_leases` | Код OTP, созданный на воркере #1, успешно проверяется на воркере #2; лимит IP делится между воркерами; `runMaintenanceJob` выполняется ровно в 1 воркере |
