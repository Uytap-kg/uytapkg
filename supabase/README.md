# Управление базой данных Supabase

В данном каталоге находится конфигурация Supabase CLI и версионированные миграции схемы базы данных проекта.

> [!IMPORTANT]
> **Главное правило:**  
> **Любое изменение базы данных — только новым файлом миграции.**  
> Запрещается вносить изменения в схему вручную через Supabase Studio / Dashboard в обход системы миграций, а также модифицировать уже применённые в production файлы миграций.

---

## 1. Структура каталога

```text
supabase/
├── config.toml           # Конфигурация Supabase CLI
├── migrations/           # Файлы SQL-миграций (YYYYMMDDHHMMSS_name.sql)
│   └── 20261012113812_enable_rls_email_verifications.sql
└── README.md             # Инструкция по работе с миграциями
```

- **Единый источник истины:** Все изменения схемы БД, хранимых процедур, индексов и RLS хранятся в `supabase/migrations/`.
- **Старые миграции:** Файлы в `back-end/src/migrations/` и `back-end/src/schema.sql` признаны устаревшими (сохранены только для обратной совместимости локальных тестов).

---

## 2. Базовый слепок схемы (Baseline)

- Первой миграцией в проект будет добавлен **baseline** — полный слепок схемы, снятый с рабочей (живой) базы данных с помощью `pg_dump`.
- Все последующие доработки (включая разделение JSON-хранилищ на реляционные таблицы баннеров, Instagram-заявок и тарифов) накладываются поверх baseline отдельными последовательными миграциями.

---

## 3. Применение миграций

Миграции применяются к целевой базе данных через Supabase CLI:

```bash
# Применение всех неприменённых миграций к удалённой базе
npx supabase db push --db-url "<POSTGRES_CONNECTION_STRING>"
```

> [!WARNING]
> Никогда не коммитьте строку подключения с паролями (`--db-url`) в репозиторий или открытые файлы. Передавайте её через переменные окружения или защищённые секреты CI/CD:
> ```bash
> npx supabase db push --db-url "$DATABASE_URL"
> ```

---

## 4. Создание новой миграции

Для добавления изменений схемы:

1. Сгенерируйте новый файл миграции с временной меткой:
   ```bash
   npx supabase migration new <migration_name>
   ```
   *Пример:* `npx supabase migration new create_banners_table`
2. Откройте созданный файл в `supabase/migrations/` и напишите идемпотентный DDL SQL-скрипт.
3. Проверьте статус миграций:
   ```bash
   npx supabase migration list --db-url "$DATABASE_URL"
   ```
4. Примените миграцию:
   ```bash
   npx supabase db push --db-url "$DATABASE_URL"
   ```

---

## 5. Политики безопасности (Row Level Security / RLS)

- В рабочей базе данных RLS включён на всех таблицах.
- Бэкенд подключается к базе данных с ключом `service_role`, который обладает правами администратора и обходит RLS (`RLS bypass`).
- Для таблиц, к которым закрыт любой прямой клиентский доступ через PostgREST (anon / authenticated), RLS включается **без создания политик**:
  ```sql
  ALTER TABLE public.<table_name> ENABLE ROW LEVEL SECURITY;
  ```
  Это обеспечивает строгое правило *default deny* для внешних запросов.
